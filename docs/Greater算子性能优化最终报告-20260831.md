## 2. 最终实现

1. P2先校验stream operand在outer维的线性连续性；混合外维广播不满足时回退通用stride路径，修复旧P2的错误线性寻址。
2. Host按真实执行路径分配核数：P1/P2使用查询到的AIV数；大于等于64MiB估算IO的连续同形张量使用全部AIV；中小generic保留实测更优的20核数值策略。
3. 所有`innerSize<=dtype TILE`的非对齐广播行均可进入row-padded批处理。通用路径本来就把每行Compare向上取整到256元素，因此旧`padding<=2x`门限只会增加地址分解和小搬运次数。
4. P2按DAV_2201的184KiB用户UB区精确规划：删除死Buffer，按dtype/方向条件分配compute Buffer，bf16/int8 batch上限为48/60KiB，其余64KiB，并用`static_assert`校验最坏总量。
5. fp16/fp32 P1使用官方Broadcast内部同类的Vector `Copy(srcRepeatStride=0)`展开resident row，把一批逐row Compare/Select/Cast合并为一次。
6. fp16/fp32 P2使用`Brcb + Copy`展开连续scalar；整核scalar集合超预算时，改为每tile加载32个half或16个float scalar，并在覆盖batch Buffer前执行V到MTE2同步。
7. Host补齐context/getter判空、rank上限、负维、广播兼容、dtype一致性、checked multiplication、uint32可表示性、raw tiling容量和返回值检查；空Tensor保持正确短路语义。

所有分派均由dtype、广播stride、对齐、数据量、UB预算和平台核数决定，没有公开或猜测shape特判。
