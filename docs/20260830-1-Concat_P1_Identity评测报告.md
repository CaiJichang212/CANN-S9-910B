# Concat P0/P1 分阶段本地性能评测

日期：2026-08-30；平台：Ascend 910B4-1 / DAV_2201；CANN：8.5.0。

## 结论

P0 未达到独立提交门禁。P1 Identity 通过本地正确性和性能门禁；随后使用
S8 Docker 重建的 `Concat_20260830_204619_zip` 官方 5/5 Pass，总时延
562.35 us，已晋升为当前官方基线。本报告的本地 92-case 汇总仍不是比赛成绩。

## 实现

- Host 使用 checked `uint64_t` 构造 shape 乘积、输入 prefix、行宽和总字节，
  序列化到现有 `uint32_t` 字段前显式检查范围。
- 默认 TilingKey `0`、完整 256 路 Tiling 和通用 Kernel 保持原路径。
- 单输入使用 TilingKey `2` 和 16 B Identity TilingData，仅携带总字节、核数和
  tile 字节数；Kernel 不再做输入扫描或行列换算。
- Identity 按实际输出地址划分唯一的非对齐 head、32 B body 和 tail，保持
  64 KiB 双缓冲；核数由运行时 AIV 数和统一最小每核字节决定。

## P0 处置

完整 `rowPeriod` 行组候选在单轮 screening 中使 92-case 总和回退 5.58%，
scoring proxy 回退 2.06%，产生 14 个 material 回退，已撤销。收敛后的安全
候选在 6 对 A/B 中中位总和改善 0.49%、无 material 回退，但只有 3/6 轮
更快，低于 4/6 门禁，也未提交。Kernel 随后恢复为官方基线路径，仅保留
不改变受支持输入 Tiling 结果的 Host checked arithmetic。

## Identity 阈值筛选

五个单输入 case 在三张卡各采一轮；每个 case 为 30 task，丢弃首条后取
29 条热态 P50。1% 噪声带内偏好更高门槛和更少核。

## 正确性

P1-128 通过完整 bitwise 门禁：48 个固定/宽行 case、三个 seed 各 100 个
随机 case、4 dtype 混合空 Tensor 契约，以及 11 组高风险重复控制。四种
公开 dtype、正负轴、rank 1-7、零长度、1/255/256 输入、特殊浮点位模式、
超 64 KiB 片段和非对齐行均通过。

每轮每版本由一个 profile 承载 `92 x 30 = 2760` 条 Concat task；版本顺序
AB/BA 交替，物理卡按 5/6/7/5/6/7 轮转。解析器逐组校验 task 数和 BlockDim。
