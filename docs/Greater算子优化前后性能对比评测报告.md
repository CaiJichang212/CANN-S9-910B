## 1. 结论（TL;DR）

| 维度 | 结果 |
|------|------|
| **整体（35 用例 prof_sum）** | **6357 µs → 3619 µs，1.76× 提速，节省 2738 µs（-43%）** |
| **显著加速（≥2×）** | **7 例** |
| **性能回退（≤0.95×）** | **0 例**（同形 / 对齐广播全部 ±3% 内，属噪声） |
| **最大单点提速** | `f16_tail_bouter`（非对齐外维广播）**932 → 66 µs = 14.2×** |
| **精度** | 优化后 35/35 全部 PASS（含 inf/-inf/NaN 注入） |
| **额外收益** | 修复优化前版本在 64KiB 标量边界（`f32_binner_16128`）的**正确性 bug**（优化前 acc=FAIL） |

**核心判断：优化有效，且方向正确。** 两项优化（`rowPadded_`、`scalarBatchPerCore_`）精准命中优化前报告（§7 P-NEW-1 / P-NEW-2）标注的最高 ROI 瓶颈，实测提速**超过**报告预期（非对齐广播预期 ~11×，实测 14×；fp32 内维预期 ~2.8×，实测 4.3×），同时对已优化场景**零回退**。优化属路径通用化（按 innerSize 对齐性 / 标量连续性几何分派，非针对特定 shape 调优），符合赛题泛化要求。

## 2. 评测方法

### 2.1 公平性保证：同设备同日 A/B
本次在**同一设备、同一天**对"优化前"与"优化后"两版 kernel 各跑一遍**完全相同的 35 用例**，确保相对比较不受环境漂移影响（两版同等承受设备争用）。同时以仓库内已提交的 [`summary.csv`](Greater/perf_test/summary.csv)（2026-07-22 采集）交叉核验——本次"优化前"数据与其一致（如 `f16_tail_bouter` 本次 932.5µs vs 报告 908.1µs，±3% 内），证明基线可复现、口径一致。

### 2.2 环境
- **硬件**：Ascend 910B4，容器内可见 **1 卡**（物理 NPU 6 → 逻辑 device 0），采集期 AICore 空闲（0%）。注：优化前报告用 device 4（8 卡可见），本次容器映射不同，故改用逻辑 device 0（已用 `acl.rt.get_device_count()=(1,0)` 核验）。
- **软件**：CANN 8.5.0 社区版，openEuler 22.03 SP4，容器内运行；私有 `pylibs`（torch 2.5.1 / torch_npu 2.5.1.post1 / numpy 1.24.0 / scipy 1.10.1）经 `PYTHONPATH` 隔离。
- **被测对象**：两版 `aclnnGreater`（`libcust_opapi.so` 覆盖内置符号），均经 `bash build.sh` 全量重建 + `.run` 安装，`.run` 比源码新（构建一致）。

### 2.3 采集与指标（与评分器同源 + 报告 §2.2 一致）
- 每用例 **warmup 5 + 测量 30 轮**，内层 `custom_op` 再循环 30 次 → 每例约 **1050 次** `aclnnGreater` 样本。
- `msprof --aic-metrics=PipeUtilization` 采集 AICore 时间 + MTE2/VEC/Scalar/MTE3 流水占比。
- **时间口径**：去前 20% warmup 样本后取**中位数**（稳态）。
- **bound** = argmax(aiv 流水 ratio)。
- **sync_gap** = `1 − aiv_time / Task Duration`（同步空等占比，[工程经验 §4.4](../算子性能评测与瓶颈分析工程经验.md)）；本指标为优化前报告未覆盖项，本次新增，用于量化 fp32 内维广播的同步停顿改善。
- **有效带宽 effBW** = `(x字节 + y字节 + z字节) / 时间`。
- **精度**：浮点注入 5% inf / 5% -inf / 5% NaN + 每行尾固定特殊值，与 `torch.gt` CPU golden 做 `torch.equal` 精确比对（bool 输出）。
- **隔离**：每例前**防御性重装** Greater `.run`（防并行算子 job 覆盖共享 `vendors/customize`）；当 device 被并行 `perf_run.py` 占用导致 `op_summary` 为空时，**自动重试至多 5 次**。

### 2.4 用例集（35 例）
- **28 例**：与优化前报告完全相同（5 dtype × 9 shape 模式），保证可逐例对照报告基线。
- **+7 例新增**：验证本次优化新覆盖的非对齐 / 边界路径——`f16_tail_bouter_rev`、`f16_tail_binner`、`f16_tail_binner_rev`（非对齐 P1/P2 镜像方向）、`f32_binner_16128` / `f32_binner_16129`（64KiB 标量边界前后）、`f16_p1_partial_tail`（部分外维复用 + 非对齐）、`f16_p2_5d_tail`（5D 非对齐）。

## 3. 优化内容概述

工作树 `greater.cpp` 相对 HEAD（+338 / −19 行）实施两项优化，**精确对应优化前报告 §7 的 P-NEW-1 / P-NEW-2**：

| 优化 | 机制 | 解决的优化前瓶颈 |
|------|------|------------------|
| **`rowPadded_`（P-NEW-1）** | 当 `innerSize % 256 != 0` 时，不再禁用 P1/P2，而是把每个逻辑行 `DataCopyPad` 到 UB 中一个 256 元素对齐槽（`ProcessResidentPadded` / `ProcessInnerBcastPadded`），驻留/批量载入仍一次完成、大 tile 内按行子 tile 循环比较，`CopyOutRows` 只回写 `innerSize` 个 bool。约束 `rowElems_ ≤ 2×innerSize` 控制膨胀。 | 非对齐广播 12× 退化（`innerSize%256` 约束致 P1/P2 失效 → 每 segment 重读广播操作数） |
| **`scalarBatchPerCore_`（P-NEW-2）** | 内维广播标量按 `IsScalarIndexContinuous` 判定：当 `scalarIndex(seg)==seg`（每核只消费自己连续段）时，按 `outerSize/blockDim` 每核分配标量，**移除 64KiB 全量标量门限**（原 `batchCount×sizeof > 64KiB` 即禁用 P2 回退慢路径）。 | fp32 `[16384,1024]×[16384,1]` 因 16384×4B=64KiB 触发门限 → P2 禁用 → 退化 414µs；同时修复该边界正确性 bug |

## 5. 关键提升分析

### 5.1 非对齐广播：14× 提速（P-NEW-1，`rowPadded_`）

| 用例 | innerSize | 优化前 | 优化后 | 瓶颈迁移 |
|------|-----------|--------|--------|----------|
| f16_tail_bouter | 1000（非对齐） | 932µs / MTE2 100% / effBW 26 | **66µs / VEC 50% / effBW 374** | 带宽全空转 → 计算受限 |
| f16_tail_bouter_rev | 1000 | 919µs / MTE2 100% / 27 | **65µs / VEC 50% / 376** | 同上 |
| f16_tail_binner | 1000 | 212µs / SCA 61% / 116 | **63µs / SCA 53% / 389** | 标量同步减半 |
| f16_tail_binner_rev | 1000 | 212µs / 116 | **64µs / 387** | 同上 |

**诊断**：优化前 `innerSize%256!=0` 使 P1/P2 全禁用 → 通用逐 segment 路径每段重读广播操作数（8192 段 → 重读 8192 次），MTE2 100% 全空转在冗余小 `DataCopyPad`，effBW 仅 26 GB/s（同形 1018 GB/s 的 1/40）。
优化后 `rowPadded_` 把每行 pad 到 256 对齐槽，驻留/批量载入一次完成、按行子 tile 循环比较，**消除冗余 HBM 读**；瓶颈从 MTE2（带宽浪费）迁移到 VEC/SCA（计算），effBW 提至 374–389 GB/s，sync_gap 从 ~0（全在 MTE2 空转）回到正常流水重叠。**提速 3.3–14.2×，且镜像方向（x 驻留 / y 驻留）均生效**，证明路径对广播方向对称、通用。

### 5.2 fp32 内维广播：4.3× 提速 + 正确性修复（P-NEW-2，`scalarBatchPerCore_`）

| 用例 | 优化前 | 优化后 | 瓶颈迁移 |
|------|--------|--------|----------|
| f32_binner [16384,1024] | 414µs / SCA 63% / MTE2 61% / effBW 203 | **97µs / MTE2 92% / effBW 863** | 标量同步未饱和 → 带宽近天花板 |
| f32_binner_16129 | 406µs / SCA 64% / 204 | **93µs / MTE2 91% / 887** | 同上 |
| f32_binner_16128 ⚠ | 96µs **acc=FAIL** | **96µs PASS** | （正确性修复） |

**诊断**：优化前 P2 的全量标量门限 `batchCount×sizeof ≤ 64KiB` 在 fp32 `[16384,1]`（16384×4B=64KiB）刚好超限 → P2 禁用回退慢路径；且 f32_binner 的 MTE2 61% / SCA 63% **双高未饱和**是典型同步空等特征（标量 `GetValue` 与 MTE2 交替串行）。
优化后 `scalarBatchPerCore_` 改为每核只载入自己连续段标量（`outerSize/blockDim`），**移除 64KiB 门限**，瓶颈从 SCA 同步迁移到 MTE2（92%），effBW 203→863 GB/s（逼近 ~1 TB/s 天花板）。**提速 4.26–4.36×，超过报告预期 ~2.8×。**

### 5.3 部分外维复用 + 非对齐：2.1×（`f16_p1_partial_tail`）
3D `[16,512,1000]×[16,1,1000]`：优化前 172µs（SCA 100%，effBW 143），优化后 80µs（VEC，effBW 306）。`rowPadded_` 同样覆盖"部分外维复用"（`residentGroupSegs_ < outerSize_` 的分组驻留）+ 非对齐组合，2.1× 提速。

## 6. 正确性与无回退

### 6.1 零性能回退
所有"已优化场景"（同形大/中/小、对齐外维/内维/双维广播、3D/5D、1D 向量、各 dtype 同形）提速比落在 **0.97–1.04**，全部 ±3% 噪声范围内，无任何 ≤0.95× 回退。带宽天花板组（`f16_same_big` 1018、`f32_same_big` 1049、`f16_vec` 1018 GB/s）前后一致，证明优化未触碰已最优的数据搬运路径。

### 6.2 ⚠ 修复优化前版本的正确性 bug（`f32_binner_16128`）
- **现象**：优化前（HEAD `30afc4f`）在 `[16128,1024]×[16128,1]`（标量 operand 16128 元素 × 4B = **恰好 64KiB**，P2 全量门限 `≤64KiB` 刚好命中启用）上 `torch.equal` vs golden **失败（acc=FAIL）**，5 次重试一致，非偶发。
- **根因**：P2 全量标量路径在该边界（`batchCount+COMP_ALIGN` 略超实际 UB 分配）对标量索引/物化越界，输出错误。同尺寸但 `innerSize=1024` 的对齐场景不受影响（走不同 UB 布局）。
- **优化后**：`scalarBatchPerCore_` 重写按核分配，96.2µs **PASS**——既保持速度又修正结果。
- **意义**：赛题隐藏用例 shape 未知，若命中此类标量边界，优化前版本将**既慢又错（0 分）**；优化后版本正确且快。这是一项超出"性能"范畴的**关键健壮性收益**。

### 6.3 精度
优化后共 **87 用例全部 PASS**（35 主对比 + 44 全矩阵补测 + 8 大尺寸跨 dtype，含 inf/-inf/NaN 注入 + int32 整数极值边界）。优化前 86/87 PASS，唯一 FAIL 即 §6.2 的 `f32_binner_16128` 边界 bug。

## 7. 整体影响与赛题含义

- **prof_sum（35 例合计）6357 → 3619 µs（1.76×，-43%）**。提速集中在非对齐广播（14×）与 fp32 内维广播（4.3×）两类——正是优化前报告判定的"最大性能风险"（赛题明确 shape 可能非对齐）。
- 若评分隐藏用例包含**非对齐广播**（如 `[A, 非对齐N]×[1, 非对齐N]`），优化前版本在此类用例付出 **12–14× 代价**且 fp32 标量边界**可能出错**；优化后版本将其拉回与对齐场景同档（66µs 级、effBW 374+ GB/s），并保证正确。这是对 prof_sum 排名与得分基本盘的**实质改善**。
- **泛化性**：两项优化均按通用几何条件分派（`innerSize%256` 对齐性、标量索引连续性、`rowElems_≤2×innerSize` 膨胀上限），**无任何针对已知 shape 的特判**，符合赛题"必须泛化、否则 0 分"的要求。新增 7 例（镜像方向 / 边界 / 高维非对齐）均通过，佐证通用性。

---

## 8. 结论

1. **优化有效**：整体 1.76×、7 例 ≥2×、0 回退；最大单点 14.2×（非对齐外维广播）。
2. **精准命中**：两项优化逐一对应优化前报告 §7 的 P-NEW-1 / P-NEW-2 最高 ROI 项，实测**超过**报告预期。
3. **额外修复正确性**：优化前版本在 64KiB 标量边界（`f32_binner_16128`）acc=FAIL，优化后修正——这是性能之外的关键收益。
4. **零回退 + 泛化**：已优化场景 ±3% 噪声内无变化；新增路径按几何通用分派，**87 用例全 PASS**（含全 dtype / 镜像 / 边界 / 高维），且大尺寸跨 dtype 实测外维广播 7.8–16.5×，证明提速非 fp16 特例。
5. **建议**：优化已达预期，可固化（提交工作树改动）并重新打包 `Greater.zip` 上板；后续若仍有余力，可按优化前报告 §7 P-NEW-3（内维广播标量物化减同步）继续压 SCA，但 ROI 已为中低。

### 9.3 已知局限（坦诚）

1. **设备争用**：采集期间有并行算子 job 间歇占用 device 0。中位(840 样本)+重试可消除瞬态干扰，但**绝对值可能比独占设备偏高 ~3%**（见基线交叉核验）；**相对提速比**因前后同等受争用而基本抵消，可信。
2. **小尺寸 dtype 扫描不显提速**：`[21,1000]` 仅 21 段，不足以触发"每段重读"退化，故 dtype-tail 小用例提速 ~1.0×——这是**用例尺寸**限制而非优化失效；大尺寸跨 dtype（§5.4）已补证提速 dtype 普遍。
3. **f32_binner_16128 根因为推断**：优化前此处 acc=FAIL 是 5 次一致的确定现象（已证），但越界机制的精确代码定位为据边界算术推断，未做单步仿真逐行确认（不影响"FAIL 事实"结论）。
4. **未量内置 aclnnGreater 基线**：Greater 在 `libopapi.so` 有内置实现，可作更公平参照（[工程经验 §3.5](../算子性能评测与瓶颈分析工程经验.md)）；本次聚焦前后对比，未单列内置基线，可作后续补充。
