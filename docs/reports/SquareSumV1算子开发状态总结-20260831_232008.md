## 5. 源码模型与已知风险

当前路由为 mode 0–7。mode 3 先以初始 `tileA0Align` 搜索 `rChunkSize`，随后在 `totalRows < coreNum` 时为增加独立 A0 owner 再缩小 `tileA0Len/tileA0Align`；缩小后没有重新搜索 `rChunkSize`。这与热点例中较多 R chunk 的观测一致，是一个可证伪候选假设，不是已证明根因。

不可破坏的风险边界：

- BF16 必须保留 FP32 Mul -> BF16 round-trip -> FP32 累加语义；
- mode 3 `DataCopyPad.blockCount <= 4095`，GM stride 按字节、UB stride 按 32B datablock；
- 改变 R chunk 会改变 fp32 归并顺序，必须覆盖 fp16/fp32/bf16、大小幅值、对齐/非对齐、R=4095/4096 与重复稳定性；
- Host 的 UB 计算、RA Reduce scratch 查询与 Kernel `InitBuffer` 必须同步；
- mode 4 仍是单核安全回退，不在本轮第一个性能候选中捆绑修改；
- rank 6–8 尚无完整真实回归，不能仅凭 Host 检查宣称全部交付。
