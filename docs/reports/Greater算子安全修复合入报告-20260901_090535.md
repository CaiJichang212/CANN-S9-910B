## 1. 修复内容与身份

1. Host逐维拒绝负维或超过`uint32_t`的输入维度，避免零元素乘积让超范围字段绕过检查。
2. blocked P2不再在循环前按整核segment数预加载scalar batch，只在循环内按32行half/16行float的已分配容量分块加载。
3. 通用scalar回退的单元素DataCopyPad后增加MTE2_S事件，再由GetValue读取。

## 2. 正确性

| 门禁 | 结果 |
|---|---:|
| Host合同（含空Tensor超大维度框架短路） | 6/6 PASS |
| P2 UB（新增blocked inner=3正反向） | 7/7 PASS |

| sweep | 85/85 PASS |

公开空Tensor路径在框架层短路，不进入自定义Tiling，因此零元素且维度`2^32`按空Tensor语义成功；当前Host源码仍对实际进入Tiling的每个维度执行独立`uint32_t`门禁。

## 3. 性能回归

同步变更按项目要求执行同设备相邻full94：

- 总和`11139.4965 -> 11162.0120 us`，回退22.5155 us / 0.202%，小于0.5%门槛。

- large/blocked P2均无material回退。
- full94单轮仅`f16_p1_n7`和`f16_p2_n33`触发tiny双阈值；两组反序8-spec复测中，前者中位改善1.66%，后者仅回退0.50%/0.019 us，全部无material回退。

## 4. 拒绝的tail初始化尝试

为响应初检RED-5/SEC-1.2，曾尝试把非对齐末段拆分并在MTE2前清零完整Compare读取区。该候选`p_large_inner_full_resident_capped_safe_tail`正确性通过，但screening中large P1回退24.9%-42.6%、large P2回退28.8%-38.3%，故立即拒绝并恢复安全父Kernel hash。

当前实现对已分配UB中的padding区可能执行非可观察比较，但只回写逻辑`n`，无GM越界或输出依赖；该条例按项目性能目标与实测证据豁免，失败patch完整保留。
