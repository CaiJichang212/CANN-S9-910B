# Greater 大 Inner 完整 P1 保守核数方案

## 1. v1 证据与新假设

v1 已用两组反序 20-spec A/B 证明 inner-slice resident 数据流有效，但 full94 暴露低工作量 `f16_5d_bcast` 从 20 扩到 28 核后 material 回退。v2 的单一参数假设是：只有 `ceil(totalSize/TILE) >= aivCoreNum`，即至少可给每个可用 AIV 一个 dtype TILE 时，large-resident 路径才突破 proven generic core cap；否则仍使用 generic cap 计算二维 worker。

这条规则只依赖总工作量、dtype TILE 和平台查询核数，不依赖任何 shape 名或官方隐藏 case。

## 2. Host/Kernel 模型

```text
usefulTiles = ceil(totalSize / TILE)
largeCoreLimit = (usefulTiles >= aivCoreNum)
               ? aivCoreNum
               : genericCoreLimit
maxUsefulCores = min(usefulTiles, largeCoreLimit)
innerWorkers = min(ceil(innerSize / TILE), maxUsefulCores)
outerWorkers = min(outerSize, maxUsefulCores / innerWorkers)
blockDim = innerWorkers * outerWorkers
```

Kernel 仍从 `blockDim` 和编译期 TILE 镜像复原 worker。预计结构：

| spec | v1 | v2 预期 |
|---|---:|---:|
| fp16/fp32 大目标 | 40 | 40 |
| `f16_5d_bcast` | 28 | 20 |
| `f16_p1_n10000` | 22 | 20 |
| partial-group/P2/短行/Generic | 原值 | 原值 |

Kernel resident、同步、尾部和 UB 预算与 v1 相同；不引入第二个性能机制。

## 3. 预声明门禁

- 正确性：专项 14/14、Host 5/5、P2 UB 5/5、mixed 40/40、sweep 85/85、full94 94/94。
- 目标：四个 fp16/fp32 正反向大-inner目标在两组相邻 A/B 中各自改善至少 10% 且 5 us。
- 诊断全局：冻结 20-spec 总和每组改善至少 10%。
- 历史共同79：总和不得回退超过 0.5%，且无逐项 material 回退。
- full94：总和不得回退，且无逐项 material 回退；压力项总和只作诊断，不要求任意固定改善比例。
- 回归：`f16_5d_bcast`、`f16_tail_bouter` 和其他控制不得回退超过 `max(5%,0.5 us)`；临界项至少两次相邻复测。
- 结构：大目标 20→40；`f16_5d_bcast` 与 N=10000 小 outer 保持 20；P2/partial/Generic 不变。

共同79不含本轮大目标，只能证明旧工作区间未回退，不能承担目标收益门禁。full94 包含大目标但额外压力项权重任意，因此用“总和不回退 + 逐项无 material 回退”而不是事后调整收益比例。
