# SquareSumV1 评分规则验收报告

测试日期：2026-07-21（UTC）  
平台：Ascend 910B（20 AICore），CANN 8.5.0，Euler/openEuler 2.10 环境  
被测包：`op_project/custom_squaresumv1/build_out/custom_opp_openEuler_aarch64.run`

## 结论

- **评分核心路径（fp16/fp32）：44/44 通过。** 校验严格采用评分规则：fp16 `rtol=atol=1e-3`、fp32 `rtol=atol=1e-4`，没有使用“允许错误元素比例”。
- **参数校验：4/4 通过。** int32、正/负越界 axis、重复 axis 都得到 `RuntimeError` 拒绝。
- **bf16：0/3 通过，不能宣称全 dtype 验收通过。** 工程注册与文档声明支持 bf16，但尾轴、非尾轴和多轴三条实测均错误；这是提交前必须修复或在接口/文档中收窄支持范围的风险。
- 性能方面，已有 Case1 上板中位 AICore 时间为 **11.831 µs**；评分所需的隐藏基线和全部隐藏 shape 未公开，因此不能据此宣称性能验收已完成。

## 执行方式

```bash
cd SquareSumV1
python3 npu_acceptance_test.py
```

脚本在进程启动时全局加载 `libopapi.so`，避免依赖运行中修改 `LD_LIBRARY_PATH`。它以
`torch.sum(torch.square(x), dim=axis, keepdim=keep_dims)` 作为 golden。

## 覆盖矩阵与结果

| 维度 | 已覆盖内容 | 结果 |
|---|---|---|
| 数据类型 | fp16、fp32；另行探测工程声明的 bf16 | fp16/fp32 44/44；bf16 0/3 |
| 取值范围 | `[-1,1]`、`[-0.01,0.01]`、`[1,10]`、`[-1000,1000]`、全零、NaN、+Inf | 通过（NaN/Inf 同值语义通过） |
| 1-D 对齐边界 | `N=1,4,31,32,33,997,10000` | 通过 |
| 2-D 与大 shape | 双轴/负 axis/keepDims；`(2024,3000)` | 通过 |
| 评分规则 6-D 示例 | `(2,3,4,5,6,7)`，axis=1，fp16/fp32 | 通过 |
| 非尾轴 ARA | A0=997；R=4095/4096/5000/10000；keepDims | 通过 |
| 多轴规约 | 连续、多轴非连续、负 axis、最高 5-D | 通过 |
| 确定性 | fp16 尾轴大规约、fp32 ARA 各重复三次 | 通过 |
| 非法参数 | int32、axis=rank、axis<-rank、重复 axis | 4/4 拒绝 |

其中 fp16 最接近阈值的实测相对误差为 `9.7561e-4`（严格小于 `1e-3`）；fp32 最大相对误差为 `2.85e-6`，明显小于 `1e-4`。

## bf16 风险明细

| 路径 | shape / axis | 结果 |
|---|---|---|
| 尾轴规约 | `(4,997)` / `-1` | 4/4 元素错误，最大相对误差 1.0 |
| 非尾轴规约 | `(4,3,997)` / `1` | 3988/3988 元素错误，最大相对误差 1.0 |
| 非连续多轴 | `(2,3,4,5,6)` / `[1,3]` | 3/48 元素错误，最大相对误差 `5.4e-3` |

问题可稳定复现，且不属于 fp16/fp32 评分路径的回归。后续若评测可能投放 bf16，应优先修复 bf16 kernel 模板的数据搬运/转换链路后重新构建 `.run` 并复跑本报告中的全部用例。
