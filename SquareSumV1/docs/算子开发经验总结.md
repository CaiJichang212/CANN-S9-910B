## 二、环境准备经验（共享 NPU 服务器）

### 选卡（最重要）
```bash
npu-smi info                                    # 查 "No running processes found in NPU X"
export ASCEND_RT_VISIBLE_DEVICES=<空闲高编号卡>  # 子进程把该卡当逻辑设备 0，无需改业务代码
```

- **绝不默认抢卡 0**（低编号卡最易被不设环境变量的用户抢占）

- `device is used (-8020)` = 目标卡被占，**换张空闲卡即可**，不是硬件损坏

### NPU 可用性核查
```python
import torch, torch_npu
print(torch.npu.device_count())   # >0 即可用；=0 是 driver/占用问题
```

- `device_count=0` + `runtime 507899 driver internal error`：driver 通信不可用（宿主机侧），容器内无法修复，需宿主机处理
- 先用此命令确认，而非轻信 npu-smi 文本

## 三、工程搭建经验

### vendor 目录与 package_name
- 算子工程 `CMakeLists.txt` 的 `set(package_name <X>)` 决定 `.run` 安装的 vendor 目录：`vendors/<X>/`
- **赛题 test_op.py/run.sh 从 `vendors/customize/op_api/lib/` 加载** libcust_opapi.so → package_name 必须为 `customize`
- `customize/` 是**共享 vendor**（concat/transpose/squaresumv1 等都装这）：同一时间仅一个算子的 libcust_opapi.so 生效（CLAUDE.md「同时仅一个 custom_ops 包」）

### libcust_opapi.so 的 l0op::Contiguous 符号（高频踩坑）
自定义算子的 `libcust_opapi.so`（aclnn L2 实现）引用 `l0op::Contiguous` / `l0op::ViewCopy` 等 CANN 辅助函数（定义在 `libopapi.so`），编译时**不链接** libopapi.so，靠运行时全局加载：
```
dlopen libcust_opapi.so → undefined symbol: l0op::Contiguous
```
**解法**：让 libopapi.so 先以 RTLD_GLOBAL 加载：
```python
import ctypes
ctypes.CDLL("libopapi.so", mode=ctypes.RTLD_GLOBAL)  # 必须在 import custom_ops_lib 前
import torch, torch_npu, custom_ops_lib
```
- 赛题框架环境通常自动全局加载 libopapi.so；开发环境 test_op.py 需手动预加载
- LD_PRELOAD=libopapi.so 有副作用（signal handler 冲突），**优先用 ctypes RTLD_GLOBAL**

### 构建安装流程
```bash
cd <算子工程>              # SquareSumV1/op_project/custom_squaresumv1
bash build.sh              # → build_out/custom_opp_{openEuler,ubuntu}_aarch64.run
bash build_out/custom_opp_openEuler_aarch64.run   # 装到 vendors/customize/
# 验证符号
nm -D $ASCEND_OPP_PATH/vendors/customize/op_api/lib/libcust_opapi.so | grep <aclnnOp>
```
- `.run` 安装到已存在 vendor 时，libcust_opapi.so 可能因版本检查跳过覆盖 → 用 `\cp -f` 强制同步，或先卸载
- 跨 vendor 同步（如 squaresumv1_custom→customize）：`\cp -rf <src>/{op_api/lib/libcust_opapi.so, op_impl/.../<kernel>, op_impl/.../config, op_proto}` 全套

### zip 提交（必须用 zip_op.sh）
```bash
# 1. 工程放到 zip_op.sh 期望路径：../op/<name>/{op_host,op_kernel,build_out/custom_*.run}

```
- zip 必须恰含 `op_host/`、`op_kernel/`、已编译 `custom_opp_*.run`，且 `.run` 须与源码（最后上板版本）匹配

## 四、Ascend C API 经验（910B / DAV_2201 / A2）

### 数据类型与算术（精度关键）
| 约束 | 影响 | 对策 |
|------|------|------|
| `Mul` **不支持 bfloat16_t**（A2） | bf16 无法直接平方 | 先 `Cast(bf16→float)` 再 `Mul` |
| `ReduceSum` Pattern 版（`Pattern::Reduce::RA`）A2 **仅支持 float** | half/bf16 不能直接 WholeReduce | 统一在 fp32 域规约 |
| `ReduceSum` 前 n 个版支持 half/float，但 half 有中间溢出截断（>65504 截 65504） | fp16 大 R 累加溢出 | fp32 累加，结果再 Cast 回 |
| `half`/`bfloat16_t` 不能直接标量 aicore 算术 | 标量运算报错 | Cast 为 float（`CAST_NONE` 保持 IEEE754） |

**统一策略**：所有 dtype 在 **fp32 域完成 square(Mul) + 累加(ReduceSum/Add)**，最终 Cast 回原 dtype。一举解决 bf16 的 Mul 限制、fp16 平方溢出、half 规约截断三个问题。

### 数据搬运（DataCopyPad）
- `DataCopyPad` 支持 non-32B blockLen（为非对齐设计），**但 2D 模式的 srcStride/dstStride 单位是 32B 块**，当 `(stride元素数 × sizeof(T))` 非 32B 倍时**截断 → 行间错位**（SquareSumV1 ARA_FULLLOAD 的 253/553 错根因之一）
- 非对齐维度（spec 允许任意维度不对齐 32B）必须用 DataCopyPad 而非 DataCopy
- 替代：逐行 `DataCopyPad(blockCount=1, srcStride=0)`（精确无错位），但多次调用有性能/偶发代价

### Vector 操作对齐
- Vector API（Cast/Mul/Add/Duplicate/ReduceSum）的 count 最好对齐 `256/sizeof(type)`（=1 个 repeat，fp32 为 64），非对齐**可能引入 NPU 偶发错误**
- TBuf 分配大小要 ≥ count（含对齐余量），否则越界偶发崩溃

### Pattern::Reduce::RA（WholeReduce 非尾轴归约）
- src 数据布局要求：被规约维（R）需按特定 stride 排列；inputGM 原始布局若 R 维不连续，需 DataCopyPad 2D 重排
- simulator 行为与 NPU 可能**不一致**（simulator PASS 但 NPU 错）→ 非尾轴归约必须 NPU 实测
- 稳健替代：用 `Add` 循环沿 R 累加（Vector Add），避开 Pattern::Reduce::RA 的布局敏感性

### 流水同步
- `DataCopyPad`（MTE/PIPE_S）与 `Cast/Mul`（V/PIPE_V）是不同 pipe，`PipeBarrier<PIPE_V>` 只等 V 不等 MTE → DMA 未完成时 Vector 读到旧数据
- DataCopyPad 后应用 `PipeBarrier<PIPE_ALL>`（或对应 MTE barrier）再接 Vector 操作

## 五、精度保证经验

### spec 阈值（赛题标准）
| dtype | rtol | atol | loss（允许不满足比例） |
|-------|------|------|------|
| float16 / bfloat16 | 1e-2 | 1e-2 | 1e-3 |
| float32 | 1e-4 | 1e-4 | 1e-4 |

- `loss` 是**允许的错误元素比例**（如 fp16 loss=1e-3 表示 ≤0.1% 元素超 rtol/atol 即 PASS），不是 rtol
- **白盒/自测脚本易误用更严阈值**（如 rtol=1e-3）造成假 FAIL；务必用 spec 的 per_dtype

### 特殊值（IEEE 754）
- NaN²=NaN、inf²=inf、(-inf)²=inf；规约时 NaN 污染求和
- 比对逻辑须含：**NaN 同判**（real 与 golden 同为 NaN 视通过）+ **inf 同号同判**
- `Cast` 用 `CAST_NONE` 保持 NaN/inf 语义

### 中间精度
- fp16/bf16 输入：平方与累加**必须在 fp32**，否则大 R 累加 / 大值平方溢出超阈值
- workspace 中间结果存 fp32，仅最终 Cast 回原 dtype

## 六、性能优化经验

### 核心原则：最小化 HBM 流量
- **一次 CopyIn，UB 内完成 square→reduce，只写回最终结果**（融合算子的核心收益）
- 避免中间 X² 落盘 HBM

### 分 axis 策略（规约算子通用）
| axis 位置 | 策略 | 效率 |
|-----------|------|------|
| 最内层（axis=-1） | 连续 ReduceSum（前 n 个版） | 最高 |
| 非尾轴 | DataCopyPad 2D 重排 或 Pattern::Reduce::RA 或 Add 循环 | 中 |
| 多值不相邻 | 逐层规约（先内后外，中间存 workspace） | 低（数据量逐层减） |

### 流水与切分
- `TQue<..., BUFFER_NUM=2>` Double Buffer 隐藏 DMA 延迟
- 多核切分按 non-axis 维度，`blockDim = GetBlockDim()` **动态取核数（勿写死）**
- UB 预算逐模板验证 ≤192KB（910B），紧极限（>95%）需关注碎片

### 性能采集
```bash
export ASCEND_RT_VISIBLE_DEVICES=<空闲卡>
cd <测试框架目录> && bash run.sh <case_num>
# get_time.py 解析 PROF_*/op_summary*.csv，报告 aclnn<Op> AICore 中位数（采样 10-30 次）
```
- msprof 循环执行算子 30 次取中位数；剔除预热算子（如 aclnnMul）

## 七、验证体系经验（分层）

| 层级 | 工具/方法 | 价值 | 注意 |
|------|----------|------|------|
| UT | gtest，测 op_host tiling 逻辑 | 快，覆盖分支判定/参数计算 | 需 op_host .so + CANN 库 |
| ST（C++） | aclnn 直调，Mock + CPU golden | 接口正确性 | NPU 不可用时 Mock 路径 |
| 白盒 | ascendc-whitebox-design skill | 路径覆盖 + 网络用例 | high（全量）/low（采样）两套 |
| simulator | msopgen sim | **NPU 不可用时的功能精度降级** | 行为可能与 NPU 不一致（见 Pattern::Reduce::RA） |
| NPU 实跑 | torch_npu/aclnn，spec 阈值 | **最终真值** | 必须选空闲卡 |

**关键**：simulator 通过 ≠ NPU 通过。Pattern::Reduce::RA 数据布局、DataCopyPad 2D、Vector count 对齐等在 NPU 可能有不同行为，**必须 NPU 实测**。

### verify_result 模板（Python）
```python
def verify(real, golden):
    if golden.dtype == torch.float32: rtol=atol=1e-4; loss=1e-4
    else: rtol=atol=1e-2; loss=1e-3
    minimum=1e-10
    g=torch.where(golden==0,minimum,golden); r=torch.where(real==0,minimum,real)
    ad=torch.abs(r-g); rd=ad/torch.max(torch.abs(r),torch.abs(g))
    close=(ad<=atol)|(rd<=rtol)
    close=close|(torch.isnan(r)&torch.isnan(g))                      # NaN 同判
    close=close|(torch.isinf(r)&torch.isinf(g)&(r.sign()==g.sign())) # inf 同号同判
    return torch.sum(~close).item() <= real.numel()*loss
```

## 八、调试经验（实战踩坑）

### 1. NPU 不可用（device_count=0）
- 先 `torch.npu.device_count()` 确认；=0 时换卡或等 driver 恢复
- 降级：simulator 做功能验证，NPU 实跑延后

### 2. libcust_opapi.so undefined symbol（l0op::Contiguous）
- ctypes `CDLL("libopapi.so", RTLD_GLOBAL)` 预加载

### 3. ARA 非尾轴归约：simulator PASS 但 NPU 全错
- 根因：Pattern::Reduce::RA 数据布局 + DataCopyPad 2D srcStride 截断
- 解法：Add 循环沿 R 累加 + 逐行 DataCopyPad（srcStride=0）

### 4. err 全在 totalRow 0 / err 不稳定（偶发）
- 诊断方向：
  - 多核 race？（单核 shape 复现即可排除）
  - Vector count 非 repeat 对齐？（对齐 256/sizeof）
  - DataCopyPad 2D blockLen 非 32B？（改逐行或对齐）
  - MTE/V pipe race？（DataCopyPad 后 PipeBarrier<PIPE_ALL>）
  - buffer 越界？（Duplicate count > TBuf 大小）
- 工具：err 元素分布（按 row/col）、多 trial 看稳定性、plog 定位崩溃层

### 5. test_op.py "not in libopapi.so"
- libcust_opapi.so 加载失败 → 先确认 libopapi.so 全局加载

### 6. cp2/cp3 validator FAILED
- 缺机器证据 JSON（test-report.json / case_manifest.json / st_dev_result.json）
- validator 以 CSV/JSON 证据为准，Markdown 摘要不算；CSV 用例数须与 target 一致

## 九、常见坑速查表

| 现象 | 根因 | 对策 |
|------|------|------|
| `device is used (-8020)` | 卡被占 | 换空闲高编号卡（ASCEND_RT_VISIBLE_DEVICES） |
